# 鸿桥 0.2.1 更新说明

日期：2026-10-30。

## 反向控制

修复 UITest 成功响应 `No Error` 被旧版的 `contains("error")` 判定为失败的问题。这会造成手机已响应第一次点击，Mac 却显示拒绝操作并关闭控制。

新版识别完整的成功响应，将真实的授权拒绝、设备断开、服务忙和普通操作失败分别处理。仅授权拒绝或断开连接会因控制错误关闭开关；服务忙时保留开关并提示重试。控制命令串行执行，界面限制排队数量，不自动重放点击，避免重复操作。

## 画面刷新

- 默认“自动”刷新，不再额外设置固定刷新等待。
- USB 最多四路采集、无线最多两路，错开启动，避免无限启动进程。
- 预览按原比例缩小到短边 720 像素，保留手机原始尺寸用于鼠标坐标映射。
- 单帧缓冲只保留最新画面，丢弃迟到和过期画面。
- 帧率按实际发布到界面的时间测量；暂停时停止新采集，恢复后不显示暂停前的在途帧。

本机完整链路测速和真机操作结果保存在 `真机验证.json`。截图命令本身仍耗时约半秒，优化能提高刷新频率，但当前尚未实现 30/60 帧连续视频投屏。该手机系统拒绝加载本次自编译的采集助手（`Permission denied`），没有修改手机安全设置，也没有将实验助手打包到应用中。

## 验证范围

在用户授权下，使用 CHZ-AL00、HarmonyOS 7.0.0.111(SP10C00E111R2P4) 进行取帧、主页及空白处点击、控制队列和暂停恢复测试。真机报告与离线检查、包内组件验证分别记录；未验证的图库、系统剪贴板和摄像头扩展不计入成功项。

连接组件继续内置，用户无需安装 SDK 或配置 HDC 路径。手机仍需开启调试并确认首次授权。
